# CLAUDE.md Template

新项目初始化时使用此模板生成 CLAUDE.md：

```markdown
# 项目：{{PROJECT_NAME}}

{{ONE_LINE_DESCRIPTION}}

## 技术栈
{{TECH_STACK}}

## 工作方式
- 任务来源：Linear 项目 {{PROJECT_NAME}}，处理状态为 Todo、对应 agent 标签的 issue
- **开始做任何 issue 前，必须先在 Linear 上将其标为 In Progress**（无论是通过 `/swf:next` 还是用户直接指定）
- 开发流程：使用 Superpowers 工作流
- 完成后：在 issue 评论记录改动摘要，标为 Done
- 如果发现需要新任务，在 Linear 创建新 issue 而非直接做

## 行为准则

> 这是科研项目。设计阶段鼓励灵活和创意，但实验和验证环节必须绝对严谨——错误结果如果发表出去，后果远比返工严重。大胆假设可以，但必须小心求证。

### 禁止自作主张
- 不确定的事 **禁止猜测，必须问**。悄悄选一个解释开始写是最大的时间浪费
- 多种理解都说得通时，**列出来让用户选**，不要替用户决定
- 做出设计决策时（选方案、改接口、切换依赖、修改算法策略等），**必须停下来问**："这是一个设计决策，要用 `/swf:adr` 记录吗？"
- 如果有更简单的方案，主动说。该 push back 就 push back

### 动手前必须想清楚
- **先理解需求，再动手**。每个任务开始前，先陈述你对任务的理解，等用户确认
- **先定验收标准**。写代码前明确"怎么算做完了"，没有验收标准不要开始
- **先读相关代码和文档**。不要凭印象写，先读 design.md 和已有代码，理解上下文
- 如果任务描述不清楚，**问，不要猜**

### 做完后必须验证
- **代码写完必须跑测试**，不要声称"应该能工作"然后交差
- **实验脚本先用小数据集 dry run 验证**，确认逻辑正确后再跑完整实验。实验可能跑好几天，跑错了返工代价巨大
- **修改已有代码后，必须跑已有测试确认没有 regression**
- **声称完成前，重新检查验收标准的每一条**，逐条确认

### 代码纪律
- 只改必须改的代码，不"顺手"改相邻代码、注释或格式
- 不加没要求的 feature、抽象、灵活性、不可能场景的错误处理
- 200 行能 50 行搞定的，重写

## 科研代码规范
- 每个涉及公式的函数必须在 docstring 里标注对应的公式来源
- 必须有数值正确性测试（用手算或已知结果验证）
- 新算法必须和已有 baseline 交叉验证
- 每个任务先定义可验证的成功标准，再动手写代码

## 实验规范
- 每次实验必须先用 `/swf:exp new` 创建记录，再跑实验
- 参数不硬编码，用 config 文件或命令行参数
- 记录里必须包含：目的、参数、环境、复现命令、结果、结论
- **跑实验前必须先用小数据或小规模参数 dry run**，验证脚本逻辑正确、输出格式正确、没有 bug，然后再跑完整实验
- 实验完成后用 `/swf:exp log` 补充结果，不要只跑不记
- 负面结果也要记录，注明失败原因和排除的方向
- results/ 目录不进 git，configs/ 和 docs/experiments/ 进 git

## 文档保护
- design.md 修改流程：先写 ADR（`/swf:adr`）记录决策，再通过 `/swf:update-design` 更新。禁止跳过 ADR 直接改 design.md
- ADR 只增不改
- 如果实现和设计有冲突，先在 issue 评论里提出，等确认后再写 ADR → 改设计
- 禁止在开发任务中顺手改 design.md

## 项目规划
当前阶段：Phase _（详见 Linear Project）

## 当前架构
参见 docs/design.md
```
